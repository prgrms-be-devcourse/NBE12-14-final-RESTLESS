### **1. 서비스 개요와 구현 범위**

주최자, 아티스트, 브랜드 등의 판매자가 물품을 경매에 등록하고, 사용자는 현재 최고가를 보면서 더 높은 금액으로 입찰한다.

경매는 공연에 연결하거나 단독으로 운영할 수 있다. 경매 한 건에는 물품 하나가 있으며, 최종 최고 입찰자 한 명이 낙찰받는다.


| 항목        | 결정 내용                      |
| --------- | -------------------------- |
| 경매 방식     | 최고가를 공개하는 가격 상승형 경쟁 경매     |
| 낙찰 금액     | 낙찰자가 직접 제시한 최종 입찰 금액       |
| 운영 구조     | 여러 경매를 동시에 운영              |
| 화면 구조     | 경매 목록 탐색 + 경매별 실시간 상세 화면   |
| 동시 참여     | 사용 가능 크레딧 범위에서 여러 경매 입찰 허용 |
| 결제 방식     | 선충전 크레딧 확보 후 낙찰 시 자동 차감    |
| 초기 크레딧 지급 | ‘크레딧 얻기’ 버튼 사용             |
| 개발 순서     | 기능 구현 → 병목 발견 → 고도화 및 검증   |


### **2. 기능 정의 및 요구사항**


| 기능       | 요구사항                                  |
| -------- | ------------------------------------- |
| 경매 등록    | 판매자가 물품 정보, 시작가, 최소 인상액, 일정, 입장 조건 설정 |
| 경매 목록 조회 | 진행 중, 예정, 종료된 경매 탐색                   |
| 경매 상세 조회 | 물품 정보, 현재 최고가, 최소 입찰 가능 금액, 종료 시각 확인  |
| 제한 경매 입장 | 지정 공연 티켓 소유자를 대상으로 입장 자격 검증           |
| 입찰       | 사용자가 금액을 직접 입력하고 조건을 만족하면 수락          |
| 실시간 갱신   | 최고가, 입찰 내역, 종료 시각, 종료 결과 변경을 화면에 반영   |
| 크레딧 확보   | 최고 입찰 금액을 다른 곳에서 사용하지 못하도록 묶음         |
| 크레딧 해제   | 다른 사람에게 최고가를 추월당하면 해당 금액을 해제          |
| 경매 종료    | 최종 최고 입찰자를 확정하고 크레딧 차감                |
| 결과 조회    | 낙찰 여부와 최종 금액 확인                       |
| 내 입찰 조회  | 참여한 경매와 최고 입찰 여부, 낙찰 결과 확인            |
| 재접속      | 최신 경매 상태와 자신의 입찰 상태 복원                |


입장 조건은 우선 **전체 회원 / 지정 공연 티켓 소유자** 두 가지를 지원할 예정.

### **3. 입찰 비즈니스 정책**


| 항목           | 확정 정책                          |
| ------------ | ------------------------------ |
| 첫 입찰         | 시작가 이상                         |
| 후속 입찰        | 현재 최고가 + 최소 인상액 이상             |
| 시작가 및 최소 인상액 | 판매자가 설정                        |
| 입찰 금액 입력     | 조건을 만족하는 금액을 사용자가 직접 입력        |
| 자기 최고가 갱신    | 현재 최고 입찰자는 같은 경매에 추가 입찰 불가     |
| 판매자 입찰       | 자신의 경매에 입찰 불가                  |
| 사용자 입찰 취소    | 수락된 입찰은 취소 불가                  |
| 화면 이탈        | 입찰 효력과 크레딧 확보에 영향 없음           |
| 최고가 추월       | 기존 입찰 기록은 유지하고 확보 크레딧만 해제      |
| 동시 경매 입찰     | 사용 가능 크레딧 범위에서 허용              |
| 입찰 없는 종료     | 미낙찰 종료                         |
| 낙찰           | 종료 시 최종 최고 입찰자가 자신의 입찰 금액으로 낙찰 |


### **4. 크레딧 정책**

```
사용 가능 크레딧 = 보유 크레딧 − 현재 묶인 크레딧 총액

```


| 사건             | 처리                       |
| -------------- | ------------------------ |
| 크레딧 지급         | 보유 크레딧 증가                |
| 입찰 수락          | 입찰 금액만큼 확보, 사용 가능액 감소    |
| 다른 사람이 최고가 갱신  | 기존 최고 입찰자의 해당 확보액 해제     |
| 낙찰 확정          | 확보액을 보유액에서 차감하고 해당 확보 종료 |
| 화면 이탈 또는 연결 단절 | 확보 상태 유지                 |


- 예시
  
  | 상황                   | 보유액     | 묶인 금액  | 사용 가능액  |
  | -------------------- | ------- | ------ | ------- |
  | 최초                   | 100,000 | 0      | 100,000 |
  | A 경매에 60,000 입찰      | 100,000 | 60,000 | 40,000  |
  | B 경매에 30,000 입찰      | 100,000 | 90,000 | 10,000  |
  | A 경매에서 다른 사람이 최고가 갱신 | 100,000 | 30,000 | 70,000  |
  | B 경매에서 30,000에 낙찰    | 70,000  | 0      | 70,000  |
  

### **5. 종료 및 시간 연장 정책**

기본 종료 시각이 있으며, 종료 직전 경쟁 입찰이 이어지면 현재 종료 시각을 연장해.

```
새 종료 시각 = max(현재 종료 시각, 입찰 수락 시각 + 연장 시간)

```


| 항목            | 확정 정책                   |
| ------------- | ----------------------- |
| 연장 대상         | 종료 전에 유효하게 수락된 새 최고 입찰  |
| 연장 횟수         | 제한 없음                   |
| 총 연장 시간       | 상한 없음                   |
| 거절된 입찰        | 연장하지 않음                 |
| 동일 요청 재전송     | 중복 입찰이나 추가 연장을 발생시키지 않음 |
| 종료 이후 입찰      | 수락하지 않음                 |
| 연장 시간의 구체적인 값 | 미정                      |


- 예시 (입찰이 들어오면 1분을 연장한다고 가정)
  
  | 입찰 수락 시각 | 기존 종료 시각 | 새 종료 시각 |
  | -------- | -------- | ------- |
  | 05:00    | 10:00    | 10:00   |
  | 09:30    | 10:00    | 10:30   |
  | 10:20    | 10:30    | 11:20   |
  

### **6. 도메인 구조 설계안(초안)**


| 구성 요소                 | 책임                                            |
| --------------------- | --------------------------------------------- |
| 경매 `Auction`          | 판매자, 물품, 가격 조건, 입장 조건, 일정, 진행 상태, 현재 최고 입찰 관리 |
| 입찰 `Bid`              | 수락된 입찰자와 금액, 시각, 처리 순서 기록                     |
| 낙찰 결과 `AuctionResult` | 낙찰자, 낙찰 입찰, 최종 금액 및 종료 결과 보관                  |
| 입장 자격 검증              | 제한 경매의 티켓 소유 및 유효성 확인                         |
| 크레딧 지갑 `Wallet`       | 보유액과 사용 가능액 관리                                |
| 크레딧 확보 `CreditHold`   | 특정 입찰에 묶인 금액과 해제 및 차감 상태 관리                   |
| 크레딧 내역                | 지급과 차감 등 크레딧 변동 추적                            |
| 실시간 전달                | 경매 변경 사항을 해당 경매 관전자에게 전달                      |


### **7. 핵심 처리 흐름**

**입찰 처리**

1. 로그인 사용자와 해당 경매의 입찰 자격을 검증한다.
2. 진행 상태와 현재 종료 시각을 확인한다.
3. 판매자 본인 또는 현재 최고 입찰자인지 확인한다.
4. 입찰 금액과 사용 가능 크레딧을 검증한다.
5. 새 입찰자의 크레딧을 확보한다.
6. 이전 최고 입찰자의 크레딧을 해제한다.
7. 입찰 기록, 최고 입찰, 종료 시각을 갱신한다.
8. 처리가 확정된 후 실시간 변경 사항을 전달한다.

**5~7번은 중간 일부만 반영된 상태로 남으면 안 됨/**

**종료 처리**

1. 연장이 반영된 현재 종료 시각을 다시 확인한다.
2. 종료 조건을 만족하면 추가 입찰을 차단한다.
3. 입찰이 없다면 미낙찰로 종료한다.
4. 입찰이 있다면 최고 입찰자를 낙찰자로 확정한다.
5. 확보한 크레딧을 차감하고 결과를 기록한다.
6. 처리가 확정된 후 종료 결과를 전달한다.

알림 전달에 실패했다고 이미 확정된 낙찰을 취소하지는 않음

### **8. 비즈니스 불변식**

불변식은 동시 요청이나 재시도가 발생해도 반드시 유지해야 하는 조건이야.


| 불변식                       | 의미                        |
| ------------------------- | ------------------------- |
| 경매당 현재 최고 입찰은 최대 하나       | 두 사람이 동시에 최고 입찰자가 될 수 없음  |
| 경매당 낙찰자는 최대 한 명           | 종료 작업이 반복돼도 결과가 중복되지 않음   |
| 입찰 금액은 가격 조건을 충족          | 첫 입찰은 시작가, 이후에는 최소 인상액 적용 |
| 판매자는 자기 경매에 입찰 불가         | 판매자 본인 입찰 차단              |
| 최고 입찰자는 자기 최고가 갱신 불가      | 자기 입찰로 가격과 시간을 올리지 못함     |
| 사용 가능 크레딧은 음수가 될 수 없음     | 여러 경매나 다른 구매에서 중복 사용 방지   |
| 진행 중인 최고 입찰 금액은 확보돼 있어야 함 | 낙찰 대금 부족 방지               |
| 추월된 입찰에 대한 확보는 해제돼야 함     | 불필요하게 묶인 금액 방지            |
| 화면 이탈로 입찰이 무효화되지 않음       | 연결 상태와 구매 책임 분리           |
| 연장으로 종료 시각이 앞당겨지지 않음      | 시간 갱신의 일관성 유지             |
| 종료 이후 입찰은 수락되지 않음         | 확정된 결과가 뒤집히지 않음           |
| 같은 요청은 중복 반영되지 않음         | 중복 확보, 차감, 연장 방지          |
| 낙찰 결과와 크레딧 차감이 일치해야 함     | 돈만 차감되거나 낙찰만 확정되는 불일치 방지  |

**11. 구현 및 고도화에서 검증할 문제**


| 시나리오                | 검증할 내용                      |
| ------------------- | --------------------------- |
