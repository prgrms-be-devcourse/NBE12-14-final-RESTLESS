# 일정

아래는 계획이며 완료 실적이 아니다. 완료 여부는 실제 구현과 테스트 결과로 판단한다.

| Phase | 기간 | 내용 |
|---|---|---|
| 1 | 11/1 ~ 11/6 | 도메인 설계와 계약: 시나리오, 불변식, 상태 머신, ERD, API, 도메인 연결 규칙, 장애와 트랜잭션 경계 |
| 2 | 11/11 ~ 11/15 | 핵심 구현과 정확성 검증: 도메인별 1차 구현, MySQL 재고 예약, MySQL 대기열, PG Mock, 구매 흐름, CI, 핵심 동시성 테스트 |
| 3 | 11/16 ~ 11/22 | 성능 관측과 병목 개선: k6 Baseline, 쿼리와 트랜잭션 최적화, 필요시 Redis/PostgreSQL 비교, ADR 정리 |
| 4 | 11/23 ~ 11/30 | 확장과 장애 검증: 필요시 다중 서버, 공유 상태와 중복 실행 검증, Fault Injection, PG 대사와 복구 |
| 5 | 12/1 ~ 12/7 | 안정화와 발표: UI 정리, 회귀 테스트, 실험 결과 정리, PPT, 리허설 (12/5까지 리허설 완료 목표) |

Property-Based Testing과 Mutation Testing은 진행 상황을 보고 우선순위를 조정한다. 특정 기술 전환은 의무가 아니다.
