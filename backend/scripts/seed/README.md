# 로컬 공통 시드

로컬 개발 DB를 비우고 모든 도메인의 시드를 정해진 순서로 넣는다. 누가 몇 번을 실행해도 같은 데이터가 된다.
부하 테스트 시드(`perf/seed/`)와는 별개다. 배포 DB에는 쓰지 않는다.

## 실행

1. `backend/`에서 `./gradlew bootRun`을 한 번 실행해 Flyway가 테이블을 만들게 한다. 시드는 그 뒤에 넣는다.
2. 저장소 루트에서 실행한다.

```bash
bash backend/scripts/seed/seed.sh          # 확인을 묻고 실행
bash backend/scripts/seed/seed.sh --yes    # 묻지 않고 실행
```

- 앱 실행이나 `npm run dev`로는 초기화되지 않는다. 이 스크립트를 직접 실행할 때만 초기화된다.
- 로컬 DB에 직접 만든 데이터도 모두 지워진다. 테이블 구조와 Flyway 기록은 그대로 둔다.
- 대상은 `backend/compose.yaml`의 개발용 MySQL 컨테이너뿐이다. 다른 호스트에는 접속하지 않는다.
- 새 마이그레이션을 받은 뒤에는 `bootRun`으로 스키마를 먼저 올리고 다시 실행한다.

## 계정

비밀번호는 모두 `0000`이다. 연락처와 주소 규칙은 perf 시드와 같다.

| ID | 이메일 | 역할 | 닉네임 |
|---|---|---|---|
| 1~100 | user001@fanq.com ~ user100@fanq.com | USER | user-001 ~ user-100 |
| 901~910 | organizer001@fanq.com ~ organizer010@fanq.com | ORGANIZER | organizer-001 ~ organizer-010 |
| 999 | admin@fanq.com | ADMIN | FANQ Administrator |

모든 계정에 기본 배송지가 있다. 받는 분은 닉네임, 연락처는 회원 ID로 정한 `010-0000-0001` 형식, 주소는 판교역 광장(경기도 성남시 분당구 판교역로 160)이다.

모든 계정에 크레딧 지갑이 있고 10,000,000 크레딧을 보유한다. 지갑 ID는 회원 ID와 같고, 지급 내역은 GRANT 거래 한 건으로 남는다.

## 도메인 시드

| 순서 | 폴더 | 담당 | 내용 |
|---|---|---|---|
| 1 | `common/` | 공통 | 위 계정과 최초 크레딧 |
| 2 | `ticketing/` | 송혜민 | [README](ticketing/README.md) |
| 3 | `drop/` | 이태호 | 판매 중, 판매 예정, 판매 종료 드롭 1~3번. [seed.sql](drop/seed.sql) |
| 4 | `auction/` | 천종원 | 진행 중 3, 시작 예정 2, 유찰 1로 경매 1~6번. 입찰·낙찰은 넣지 않는다. [seed.sql](auction/seed.sql) |
| 5 | `fanmeeting/` | 팬미팅 담당 | 아직 없음 |

## 도메인 시드 규칙

- 폴더에 `seed.sql` 하나를 둔다. `seed.sh`가 비운 DB에 순서대로 넣는다. 새 도메인은 `seed.sh`의 `domains`에 이름을 넣는다.
- ID를 직접 적는다. 자동 증가에 기대면 다른 도메인 시드가 바뀔 때 내 ID가 밀린다.
- 공통 계정을 쓴다. 계정이 더 필요하면 자기 구역의 ID로 만든다.
- 시각은 `UTC_TIMESTAMP(6)` 기준으로 적는다. 다시 실행하면 판매 기간 같은 값이 지금 기준으로 다시 맞춰진다.
- 외래 키 검사를 끄지 않는다. 다른 도메인의 행이 필요하면 순서가 앞선 도메인의 고정 ID를 쓰거나 자기 구역에 직접 만든다.

### ID 구역

여러 도메인이 같이 쓰는 테이블(`users`, `venues`, `concerts`, `orders`, `payments` 등)은 구역을 나눈다.

| 구역 | 주인 |
|---|---|
| 1~999 | 공통 계정 |
| 1000~1999 | 티켓팅 |
| 2000~2999 | 드롭 |
| 3000~3999 | 경매 |
| 4000~4999 | 팬미팅 |
| 10000~ | 화면에서 새로 만든 행. `seed.sh`가 마지막에 모든 테이블의 자동 증가 시작값을 10000으로 옮긴다 |

자기 도메인만 쓰는 테이블(`drops`, `auctions` 등)은 1부터 자유롭게 쓴다.

티켓팅 시드는 지금 자동 증가 ID를 쓴다. `seed.sh`가 DB를 비운 뒤 공유 테이블의 시작값을 1000으로 옮기고 실행하므로, 실행할 때마다 같은 ID를 받는다.
