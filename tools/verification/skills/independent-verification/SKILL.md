# 독립 검증

공유 문서는 판정 기준이다. 구현자의 설명은 검증할 주장이다. 아래 순서와 기록 형식을 사용한다.

## 1. 사전 반례

별도 새 세션 또는 대화 이력이 없는 검증 에이전트에서 시작한다. 입력은 작업 요구사항, 기준 ref, 대상 SHA, 저장소 지침과 합의된 계약·불변식이다. 구현 보고서·구현자의 결론은 이 단계 뒤에 읽는다.

이슈·기준 SHA·대상 SHA가 없으면 먼저 확보한다. 합의 문서도 출처와 버전(저장소 SHA 또는 확인 날짜)을 기록한다. 먼저 `.ai-output/verification/<issue>/precheck.md`에 입력·SHA와 다음을 기록한다.
- 영향받는 불변식과 관찰 가능한 성공/실패 조건.
- 경계값·재시도·동시 실행·외부 결과 불명 중 관련 반례, 예상 결과와 근거. 해당 없으면 이유.
- 공유 가정, 가정이 틀렸을 때의 반례, 확인할 별도 근거(DB 규칙, PG 공식 문서, 실제 실행 등).

이미 보고서를 읽었다면 그 사실을 기록하고 새 컨텍스트 검증자에게 위 입력만 전달한다. 분리할 수 없으면 독립 검증은 `미완료`다. 시간이 부족하거나 작성자가 테스트 PASS라고 해도 이 상태를 승인으로 바꾸지 않는다.

## 2. 대조와 실행

사전 기록 뒤 diff·구현 보고서를 읽는다. 기준 ref와 SHA를 고정하고 실제 diff를 확인한다. 아래 세 축을 따로 판정한다.
1. Standards: 저장소 규칙·경계·불변식 준수.
2. Spec: 요청 누락·잘못된 동작·범위 초과.
3. Assumptions: 명세 자체의 누락·모순과 공유 가정의 근거.

저장소 `docs/testing/strategy.md`에서 변경 유형별 검사를 선택하고 선택/제외 이유를 적는다. 직접 실행한 명령·종료 코드·로그·대상 SHA, 환경과 DB/PG mock 설정, dirty diff 식별을 남긴다. 드롭은 dev 사본의 하네스를 포함해 기존 검증 절차를 따른다. 코드가 바뀌면 이전 결과의 적용 범위를 재평가하고 필요한 검사를 다시 실행한다. 작성자 로그는 참고 증거로 표시한다.

정책의 경계는 기존 루트 지침이 우선한다. [검증 절차](../../../../docs/testing/independent-verification.md)의 표는 그 경계를 명료화하는 채택 대기 제안이다. 미채택을 근거로 기존 보호를 완화하지 않는다. 명세의 빈칸을 근거로 핵심 정책을 확정하지 않는다.

## 3. 판정 기록

`.ai-output/verification/<issue>/review.md`에 아래 필드를 모두 채운다. 해당 없음도 이유를 쓴다.

| 필드 | 내용 |
|---|---|
| 대상 | 이슈, 기준 ref/SHA, 검증 SHA, 작업 트리 변경 여부 |
| 검증자 | 구현자와의 관계, 새 컨텍스트 여부, 선열람 여부 |
| 스킬 | 실제 읽은 SKILL.md 경로와 버전(저장소 SHA) |
| 사전 반례 | precheck 경로, 입력과 예상 결과 |
| 세 축 판정 | Standards / Spec / Assumptions 각각 통과·실패·판정 불가와 근거 |
| 실행 증거 | 명령, 종료 코드, 로그 경로, 실행 시각, SHA; 미실행은 명시 |
| 정책 쟁점 | 근거 문서, 미결정 사항, 사람에게 필요한 선택과 영향 |
| 미검증 | 환경·시나리오·자료 부족과 남은 위험 |
| 최종 판정 | PASS / FAIL / INCOMPLETE, 적용 범위 |

동일 구현자의 자기 검증은 참고 결과다. 새 컨텍스트의 다른 검증자 또는 사람이 위 절차로 추가 검토하기 전에는 독립 검증 PASS를 선언하지 않는다. 새 컨텍스트도 같은 모델의 편향을 완전히 제거하지는 않는다.

확인된 위반이 있으면 FAIL로 기록하고 미검증 범위도 병기한다. 위반 확인 없이 필수 증거·독립 검토가 부족하면 INCOMPLETE다. 필수 검사와 세 축 대조가 끝난 범위에만 PASS를 부여한다.

PASS 대상은 커밋된 깨끗한 작업 트리로 고정한다. 사전 검토를 dirty 상태에서 했으면 최종 커밋과 대조하고 필요한 검사를 다시 실행한다. 스킬 SHA와 실행한 하네스의 ref/SHA도 따로 기록한다. 개인 하네스처럼 Git 버전이 없으면 실행 파일의 SHA-256과 로그를 보관한다.

## 4. 결함의 누적

잡은 결함마다 원인 → 재사용할 규칙 → 회귀 테스트/자동 검사 → 수정 커밋을 연결한다. 자동화가 부적합하면 이유와 수동 확인 절차를 남긴다. 규칙 정본 한 곳을 고치고 다른 지침은 링크한다. 알려진 mutants 통과와 검증 완전성을 구분한다.
